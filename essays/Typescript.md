Introduction:

This paper reflects on the experience of learning TypeScript programming language and the Athletic Software Engineering style of learning that was used in University of Hawaii at Manoa, ICS 314 Software Engineering. 


TypeScript:

TypeScript is a typed superset of JavaScript so when starting the course JavaScript is the first language you are introduced to. JavaScript is used on nearly every website to make pages interactive, dynamic, and responsive to user actions. Without JavaScript, the internet would consist entirely of static text, images, and basic layouts that require a full page reload every time you click something.

JavaScript was originally designed as a lightweight scripting language for web pages. but as web applications grew, its design choices became major liabilities. A issue that was mentioned during class was that it used a loose type system which means variables can hold any data type and change types automatically. This makes it prone to runtime type errors. TypeScript since it a typed superset does everything that JavaScript does but enforcing strict typing. Other thing that TypeScript added was modularity, encapsulation, and class structures. 

The relevance of TypeScript in Software Engineering is that TypeScript was created by Microsoft to solve the challenges of developing large-scale, complex applications with JavaScript. TypeScript is a highly effective language from a software engineering perspective. It catches errors at compile time, preventing many bugs from reaching the production environment. TypeScript also acts as self-documenting code. Because variables and functions have explicitly declared types, the code explains its own data requirements. This if useful for large-scale projects and team collaboration, as it makes the code more readable another developer.


Athletic Software Engineering learning model:

Athletic Software Engineering is a hands-on learning methodology that utilizes in class time limits exercise called WODs (Workouts of the Day) to help you acquire mastery of the concepts of the course. 
The WODs are to balance both code quality with development speed. The core principle of this approach is that working quickly while maintaining good coding form which will be a useful skill in the professional setting. 

WODs are a central component of this learning style and proved to be highly useful. The WODs were intentionally designed to be ambiguous. They frequently contained bad data, incomplete requirements, or missing information. This give autonomy to the student to decided what was best for the code and look for information form credible sources outside the WODs to make a program that best fit the given requirements.

This hands-on approach is highly effective for learning software engineering, as it builds practical skills. However, it is important to note that this specific style of timed, repetitive practice might not fit well for other academic subjects.
